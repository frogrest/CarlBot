PROJECT:
Create a safe fake/emulated environment for an autonomous technical-support AI assistant for CCTV/AI-box/helpdesk operations. The system must reduce repetitive investigation work while keeping humans responsible for physical repairs, consequential changes, approvals, and final judgment.

CORE SYSTEM:
1. Fake Helpdesk
   - Tickets, comments, technician notes, statuses, root causes, resolutions.
   - Historical incidents that the agent can search.
   - API for reading/updating tickets.
2. Fake Operations Portal
   - Simulated IP cameras, NVRs, AI Boxes, network state, RTSP state, site relationships.
   - APIs for health, ping, TCP/port checks, RTSP checks, asset discovery, logs/status.
   - Fault injection for realistic incidents.
3. Autonomous Agent
   - Runs continuously as a service.
   - Watches for new/problem tickets and portal faults.
   - Investigates automatically.
   - Searches historical tickets and project documentation.
   - Produces evidence-backed diagnosis.
   - Recommends technician actions.
   - Performs only explicitly allow-listed, reversible automatic actions.
   - Verifies every automatic recovery.
   - Updates tickets with evidence, diagnosis, actions, and outcomes.
   - Escalates when human work or approval is required.
4. Knowledge Layer
   - Use project docs and user-provided documents as the authoritative knowledge source.
   - Add a simple retrieval/RAG-ready architecture; keep it replaceable.
5. Technician workflow
   - Human-readable AI findings, next actions, pending-technician state, verification after human action.
6. Evaluation
   - Deterministic simulated scenarios with known expected diagnoses/actions.
   - Tests for normal operation, faults, recovery, escalation, and regression.

AGENT SAFETY MODEL:
Classify actions as:
A. READ — automatically allowed: health, ping, logs, RTSP tests, ticket search, documentation retrieval.
B. SAFE/REVERSIBLE — automatically allowed only when explicitly allow-listed: reconnect stream, restart simulated service, retry upload, clear simulated transient state.
C. APPROVAL REQUIRED — never perform automatically without a human approval mechanism: credential changes, network changes, NVR/AI Box reboot if treated as consequential, configuration changes, firmware actions.
D. HUMAN ONLY — physical repair, cable replacement, camera replacement/movement, factory reset, production network/security changes.
The policy engine must enforce these rules independently of the model prompt.

AGENT BEHAVIOR:
Observe → Understand → Gather Evidence → Retrieve Knowledge → Form Hypothesis → Test Hypothesis → Decide → Execute Safe Action or Request Technician Action → Verify → Document → Learn from Actual Resolution.
The agent must distinguish:
- observed facts
- retrieved historical evidence
- hypotheses
- confidence
- recommended action
- actions actually performed
- verification result
It must never invent device state, ticket history, tool results, or successful repairs.

Add a fault if needed to make the scenarios realistic.

AUTONOMY:
The agent must be persistent/event-driven rather than a one-shot script. It should:
- poll or consume simulated events on a safe interval
- create or update incidents
- avoid duplicate tickets for the same active fault
- re-arm after a fault is resolved so a later occurrence becomes a new incident
- maintain agent state/history
- have retry limits, timeouts, and an escalation stop condition
- never loop forever on a failed action
